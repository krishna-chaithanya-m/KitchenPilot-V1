# Stage D — Dense Semantic Retrieval Guide

## 1. Overview & Objectives

Stage D introduces dense semantic candidate retrieval to **KitchenPilot-V1** using the pretrained sentence embedding model **`BAAI/bge-small-en-v1.5`** alongside the existing sparse lexical retrieval model (**TF-IDF** + cosine similarity).

```text
                                FastAPI Request
                                       │
                                       ▼
                             Recommendation Service
                                       │
                    ┌──────────────────┴──────────────────┐
                    │                                     │
                    ▼                                     ▼
             TF-IDF Retriever                     Semantic Retriever
                    │                                     │
             (17,045 terms)                       (BGE-small-en-v1.5)
                    │                                     │
                    ▼                                     ▼
             TF-IDF candidates                     BGE candidates
             (Lexical overlap)                    (Dense semantic)
                    │                                     │
                    └──────────────────┬──────────────────┘
                                       │
                                       ▼
                                Candidate Union
                           (Deduplicated by recipe_id)
                                       │
                                       ▼
                             Existing Hybrid Ranker
                    (0.40 Sim + 0.25 Ing + 0.20 Nut + 0.15 Pref)
                                       │
                                       ▼
                             Final Recommendations
```

### Key Stage D Guarantees
1. **Zero Disruption to V1 Baseline**: The default configuration remains `SEMANTIC_RETRIEVAL_ENABLED=false`. All existing V1 recommendation logic, TF-IDF matrices (6,871 × 17,045), vocabulary, ranking weights, and test baselines are completely preserved.
2. **Deterministic Representation**: Recipes and queries are converted to natural semantic texts deterministically without internal IDs, database hashes, timestamps, or arbitrary numeric identifiers.
3. **Reproducibility**: Artifacts generated by `scripts/build_semantic_index.py` preserve deterministic recipe ordering (`recipe_id` ascending), L2 normalization, and cryptographic SHA256 checksums.
4. **Fast Vector Inference**: Precomputed embeddings are L2-normalized; cosine similarity against all 6,871 recipes is computed as an optimized single matrix-vector dot product in $<1\text{ ms}$ on CPU.

## 3. Recipe & Query Representations

### Recipe Representation (`src/retrieval/corpus.py`)
Deterministic text construction function: `build_recipe_semantic_text(...)`.
- **Included fields**:
  - `recipe_name`: Clean recipe title (e.g., `Masala Karela Recipe`)
  - `cuisine`: Regional/national culinary style (e.g., `Cuisine: Indian`)
  - `region`: Geographic region (e.g., `Region: South Indian`)
  - `meal_type`: Course or meal classification (e.g., `Meal Type: Side Dish`)
  - `category`: Category when distinct from meal type
  - `diet`: Dietary attributes combining `diet_type` and flags (`Diet: Vegetarian, Jain`)
  - `ingredients`: Clean comma-separated canonical/linked ingredient names from `recipe_ingredients_linked.csv`
- **Explicitly Excluded fields**:
  - Recipe ID (`R00001`), database primary keys, source IDs (`M001`), source licenses, internal hashes, timestamps, numeric nutritional values.

### Query Representation (`src/retrieval/corpus.py`)
Deterministic query constructor: `build_query_semantic_text(...)`.
- Takes free-form natural language query strings (e.g. `"vegetarian South Indian breakfast with lentils"`) or structured combinations of ingredients, cuisine preferences, meal types, and dietary restrictions.

## 4. Common Retrieval Abstraction

Stage D introduces a shared interface in `src/retrieval/base.py`:

```python
@dataclass(frozen=True)
class RetrievalResult:
    recipe_id: str
    score: float
    rank: int
    retrieval_method: str  # 'tfidf' or 'semantic'

class Retriever(Protocol):
    def retrieve(self, query: str, top_k: int = 10) -> List[RetrievalResult]: ...
```

- **`TFIDFRetriever`** (`src/retrieval/tfidf.py`): Wraps the existing `TFIDFModel` without changing its internal methods.
- **`SemanticRetriever`** (`src/retrieval/semantic.py`): Vectorized dot product over `models/retrieval/semantic/recipe_embeddings.npy`.
- **`HybridCandidateRetriever`** (`src/retrieval/hybrid.py`): Union of top candidates across active retrievers with provenance tracking (`tfidf`, `semantic`, `both`).

## 8. API Integration

### Dedicated Semantic Endpoint
- **URL**: `POST /api/v1/recommend/semantic`
- **Request Body**:
  ```json
  {
    "query": "vegetarian South Indian breakfast with lentils",
    "top_k": 5,
    "user_preferences": {
      "vegetarian": true
    }
  }
  ```
- **Response**: Standard `RecommendationResponse` with `RecommendationItem` objects containing explanations, macro breakdown, and scores. Never exposes raw vector embeddings.

### Rollback & Invariance Guarantee
- When `SEMANTIC_RETRIEVAL_ENABLED=false` (default):
  - The semantic model is not loaded.
  - Existing endpoints (`POST /api/v1/recommend`, `/api/v1/recommend/by-ingredients`, `/api/v1/recipes/{id}/similar`) retain exact V1 behavior.
- When `SEMANTIC_RETRIEVAL_ENABLED=true`:
  - Missing or corrupted artifacts raise clear startup/readiness errors (HTTP 503) instead of silent failure.
